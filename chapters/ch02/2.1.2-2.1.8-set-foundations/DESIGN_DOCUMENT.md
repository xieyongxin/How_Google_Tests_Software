# AddUrl 概念项目设计文档

> 文档状态：概念验证阶段。该文档会随着项目从原型走向正式立项而更新。

## 1. 目标

验证用户输入一个 HTTP/HTTPS URL 后，系统能否完成基本校验，并将 URL 记录到一个可查询的索引中。概念验证成功的条件是：有效 URL 被接受并可查询；无效 URL 被拒绝且不污染索引。

## 2. 背景与非目标

搜索索引的正式实现可能需要网络服务、RPC、持久化存储和异步处理。本阶段只验证核心价值假设，不承诺生产性能、并发、安全认证、真实网络协议或持久化可靠性。

## 3. 团队结构

| 角色 | 当前职责 |
| --- | --- |
| 项目发起人 | 提供 URL 提交和查询的用户场景 |
| Tech Lead | 维护边界、路线图和技术决策 |
| SWE | 编写原型和核心小型测试 |
| SET | 审查可测试性，提出 fake、错误注入和自动化方案 |

## 4. 最小系统边界

```text
URL 输入
   ↓
AddUrlPrototype.validateAndAdd
   ├── UrlValidator：格式与协议校验
   └── InMemoryIndex：保存已接受的 URL
```

原型只提供进程内 API。正式项目将把输入解析、后端服务和索引存储拆成独立接口，并通过 Protobuf 描述跨服务协议。

## 5. 风险

| 风险 | 影响 | 当前处理 | 正式立项后的处理 |
| --- | --- | --- | --- |
| URL 规则过于宽松 | 错误数据进入索引 | 使用 URI 解析和协议白名单 | 增加协议契约测试和安全策略 |
| 索引只存在内存 | 进程重启后数据丢失 | 明确标为原型限制 | 引入 `IndexStore` 和文件/数据库实现 |
| 依赖不可替换 | 难以写小型测试 | 原型使用小接口 | 全面依赖注入和 fake |
| 超时未建模 | 无法验证异常路径 | 概念阶段暂不实现网络调用 | 在正式服务中注入可控延迟依赖 |

## 6. 测试策略

- 原型阶段：验证 URL 校验、成功写入、无效输入不写入三个核心行为。
- 正式立项后：SWE 维护小型测试；SET 提供 fake、错误注入和中型/大型测试。
- 所有测试必须独立、可重复，不依赖公网、固定端口或共享持久化数据。

## 7. 路线图

1. 完成概念验证并确认用户场景。
2. 评审可测试性和自动化计划。
3. 正式立项后定义 Protobuf 协议。
4. 实现 AddUrlFrontend、AddUrlService 和 IndexStore。
5. 建立 Small/Medium/Large 测试与持续集成。

## 8. 验收标准

- 有效 HTTP/HTTPS URL 可以被接受并命中内存索引。
- 无效协议、缺少主机或空输入返回拒绝结果。
- 无效输入不会修改索引。
- 文档检查脚本通过，且 SET 评审建议已记录。
