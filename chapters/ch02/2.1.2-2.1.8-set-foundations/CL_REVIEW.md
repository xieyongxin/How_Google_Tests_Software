# 模拟 CL 审查记录

本文档模拟一个小而可审查的变更列表。它不替代真实代码托管平台，而是让学习者看到 SWE、SET 和构建角色如何共同把变更推进到绿色状态。

## CL：完成 AddUrl 概念验证

### SWE 提交说明

- 变更目标：验证有效 URL 可以进入内存索引。
- 非目标：不引入网络服务、RPC 或持久化。
- 测试：有效 URL、非法协议、空输入和重复提交。
- 本地验证：`mvn clean verify`、原型命令行运行。

### SET 第一轮意见

1. URL 校验规则必须明确协议白名单，不能只判断字符串非空。
2. 失败请求必须证明不会污染索引。
3. 索引应通过小接口暴露，方便正式服务阶段注入 fake。
4. 设计文档应记录原型阶段不做超时测试的原因。

### SWE 修改

- 使用 `UrlValidator` 集中处理 `http`/`https` 和主机校验。
- `AddUrlPrototype` 只在校验成功后写入索引。
- `InMemoryIndex` 提供 `contains` 和 `size`，保持实现可替换。
- 在设计文档中补充风险、边界和后续路线图。

### 绿色提交条件

- 编译无错误和警告。
- 所有小型测试通过。
- 设计文档检查通过。
- SET 的每条意见都有代码或文档回应。
- 变更保持小范围，正式网络服务另开后续 CL。
