# SET 可测试性与自动化计划评审

评审人：SET（模拟）  
被评审人：Tech Lead、SWE  
评审阶段：概念验证完成、正式立项之前

## 评审结论

原型可以继续用于验证产品想法，但不能直接演进为生产服务。通过以下改进，后续 AddUrl 服务可以在不修改业务逻辑的情况下进行小型、中型和大型测试。

## 评审意见与处理

| 类别 | SET 观察 | 决定 |
| --- | --- | --- |
| 依赖注入 | 原型把校验器和索引作为构造参数，已经可以替换 | 保留该结构，正式服务继续使用构造器注入 |
| 接口隔离 | `InMemoryIndex` 仍是具体类 | 正式立项时抽取 `IndexStore` 接口，并提供内存、文件 fake |
| 错误注入 | 概念阶段无远程依赖，无法模拟 RPC 错误 | 在服务阶段增加可配置 fake 和结构化错误 |
| 超时控制 | 原型没有网络调用，暂不加入伪造超时 | 正式协议定义 deadline，前端测试必须覆盖超时 |
| 测试钩子 | `snapshot` 和 `size` 只用于诊断，不改变业务流程 | 保留只读观察接口，禁止生产代码依赖测试专用状态 |
| 自动化范围 | 原型只需要快速的 URL 行为测试 | 服务阶段先隔离高风险接口，再逐步增加中型和大型测试 |
| 可维护性 | 原型明确标记为可丢弃，避免过度设计 | 立项后重新评审设计，不承诺原型实现长期兼容 |

## 自动化计划

1. **快速反馈**：每次 SWE 修改先运行原型小型测试和设计文档检查。
2. **接口隔离**：正式服务以 `IndexStore`、后端服务和 HTTP 适配器为边界，使用 fake 控制异常条件。
3. **中型验证**：验证 Frontend、Service 和内存存储之间的交互，不依赖公网。
4. **大型验证**：只保留少量完整 HTTP 和文件存储路径，避免过早建立脆弱的端到端套件。
5. **结果公开**：下一实验使用统一 Maven 报告和后续测试执行器汇总结果。

## 评审验收

- 设计文档中有明确的系统边界、接口、风险、测试策略和验收标准。
- 原型小型测试不访问网络、不写固定目录、不依赖测试执行顺序。
- 每条暂不实现的建议都有阶段性理由和后续归属。
